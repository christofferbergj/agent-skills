## Local adaptations to preserve

The wording is first-party. These are the principles taken from the source and the deliberate departures.

The lettered `Next` list and the departures that compare against Oliver's rules refer to the workshop's `replies.md` at `ed7f6da`. addystack doesn't ship that file, so the list is kept on purpose as this skill's own rules, and the departures hold against that last tracked version.

Adopted principles:

- One or two lettered options of at most 12 words, `a` recommended and `b` only when the reply stops for the user's call, as its no and smallest option, offered as the turn's only question only where the user must act, after a question, or while only external work remains.
- `a` names every push, post, or issue it creates in a word or two, leaves its plan with the agent, and changes no PR or issue state the user didn't ask for.
- The agent does what a CLI, Executor, an MCP server, or computer control can do; while the next step waits, it does the independent work first; filler and options passed over twice drop out.
- A question asking the agent to act is done, and a change that a which, when, whether, or why question implies becomes option `a`, as in upstream's router.
- Finished work ends with Done, one line naming what is still open, and no options, and a push to a branch someone else owns, or one that would dismiss an approval, is a point only the user can pass.
- Items go by name in options, summaries, and handoffs, and the user answers with a letter, a letter and a tweak, or their own words, without option lines.
- A SessionStart hook loads the rules into every top-level session in both hosts, including resumes and compactions. Both hosts' hook documentation gives native subagents their own SubagentStart event, so they skip the rules; on 2026-10-20 a fresh T3 Code Claude session received the installed hook's rules and recognized the delegated-task exemption, and a fresh T3 Codex session did the same once the hook was trusted at the user's request.

Departures:

- Only the next-step and Done endings are taken here. Reply-shape's glance, decision card, and writing rules live in /reply-shape, whose own record tracks them.
- Oliver's router stops become a list of points only the user can pass, beside /principle-never-block-on-the-human, which owns working on without asking.
- A handoff table names the usual next stage in this library's flows.
- Under a full-autonomy grant, calls the grant covers are decided and reported, and a scope, interface, or product call left to the user gets an applied default with plain-words alternatives and no letter, as /pstack-mode's autonomy rule asks. The other points only the user can pass, such as a merge, a force-push, or a message to a person, keep lettered options, although /pstack-mode never gives a shorthand token to type back. The user asked on 2026-10-27 to keep this skill's lettered format, so only a defaulted call goes without a letter.
- After an answer to a question or a read-only request, options appear only when a follow-up needs the user's choice, and the turn otherwise ends with Done. Oliver's rules end every answer with `Next`, which padded answers with options nobody needed.
- A turn that ends while something the agent started will wake it, such as its own subagent, ends with one plain line of what it will do next. Oliver's rules have the agent wait for its subagent but give no ending for a turn that stops meanwhile, so agents filled it with a lone `a` that read as a choice the user had to make. Upstream now ends that turn on reply-shape's ⏳ headline and one `then:` clause naming what the agent does when the work lands, with no notes and only when nothing else is left (eda28f0, 36353a6, 8fbad09). That carries the same facts in another format; the plain line stays (owner decision, 2026-10-21), and /reply-shape's ⏳ line carries the elapsed and remaining time, naming what comes next only mid-turn.
- The hook is TypeScript run by Node, reads an installed reply skill's `SKILL.md` up to its setup pointer, this one by default and /reply-shape in a second entry, names the skill from its frontmatter, and warns at 8,000 characters to stay under both hosts' per-hook context caps.
- The hook skips T3 Code's delegated tasks through the same state-database lookup as Oliver's, read through Node's built-in SQLite and failing open, but without his `Reply rules: on` opt-in, which no workflow here uses, and without his coordinator-worker rule (18af123), whose `Worker of: t3-thread://` marker only his coordinator skill writes. The rules and /swarm's briefs still tell delegated tasks elsewhere to report without options.
- The agent offers a PR watch as an option the user picks, and starts one only when asked. Like upstream's watch (5ff1719), it is offered only when it has something to wake on, judged by the PR's own checks, bots, and reviews rather than upstream's test for workflow files, since external CI, deployment checks, and review bots report on PRs in repositories without `.github/workflows`. Oliver's rules start the T3 watch in the same turn the agent pushes or opens the user's PR. Owner decision, 2026-10-23: keep the opt-in, because a watch lets the agent act after the turn, moves the thread out of the T3 inbox, and /pstack-mode's PR playbook starts no babysit until the user asks. Upstream also ends on the running watch's ⏳ line when nothing else is left; here the watch is `a` instead.
- Beside an `a` that watches a PR or marks it ready, `b` offers /babysit-and-ship, which takes the PR through Pstack's Babysit and Shipping playbooks to merged, and it stays on offer when passed over, since the owner asked for it beside every such `a`. Upstream's `b` is only the no on a call that stops for the user. In the user's 200 T3 threads from 2026-10-20 to 2026-11-02, they asked in their own words for a merge once the PR was good to go and CI green 54 times in 51 threads, and reached a merge through a watch pick and then a merge pick 52 times, while the no `b` was offered 33 times from 2026-10-31 and never picked (owner decision, 2026-11-02).
- A draft PR with code /thermos hasn't seen gets `a` as a /thermos pass over the whole PR that fixes its in-scope findings, re-reviews the fixes with /review-loop, then marks the PR ready, and while that line applies the /babysit-and-ship `b` runs the same pass first. The pass's fixes, /review-loop's included, and a rebase that keeps patch-ids count as seen, and a PR that fits /review-loop's small-diff tier skips that line. Upstream has no such line. In the user's T3 messages from 2026-10-26 to 2026-11-02, 17 replies in 15 threads answered a mark-ready, watch, review-request, or merge step, or a finished turn on an open PR, by asking for a final Thermos or /review-loop pass first, four of them after /review-loop had already passed. All nine from 2026-10-31 on named Thermos (usage review, 2026-11-02). The babysit route, the fix re-review, and the cadence follow a council of GPT Sol and Claude Opus that the owner accepted on 2026-11-08: picking `b` had skipped the pass, and its fixes had landed after the Clean /review-loop head without review.
- Code that no /review-loop or /thermos pass has seen, where the /thermos line doesn't apply, gets `a` as /review-loop over it with its findings fixed, then the step that ships it, such as opening or updating a PR, merging, or deploying, and work in that state never ends on Done. On a PR, `b` runs the same review before /babysit-and-ship. Upstream has no such line. In the user's T3 messages from 2026-11-03 to 2026-11-10, 38 replies in 26 threads answered a watch, PR, push, merge, or deploy option, or a Done ending, on changed code by asking for a /review-loop or Thermos pass with its fixes first; 24 named /review-loop. In 26 of the 31 checked on this machine, the reply before had run no review (usage review, 2026-11-10).
- An answer outside /pstack-mode whose next step changes code gets `a` as /pstack-mode to make it, unless a coordinator owns the work or the edit is trivial or agent config, and picking an option is the user invoking the skill it names. Every skill the rules offer is model-invoked, and the seven that were user-invoked got descriptions that limit triggering to the user naming or picking them, because Claude Code refuses a user-invoked skill the agent loads after a bare letter (ADR 0007, revised 2026-11-09); a session-start test keeps the offered skills loadable. ADR 0007 chose this offer over automatic routing: in a 2026-11-02 analysis of the owner's threads, they typed the mode by hand partway through 15 threads where an answer turned into a change. The handoffs also follow Matt Pocock's session-count rule: /grill-with-docs goes to /pstack-mode for a build that fits one session and to /to-spec for one that spans several, /to-tickets goes to /coordinator for a multi-PR graph, and /wayfinder goes to /to-spec. Upstream has no such lines.
- Options keep the do-it-yourself rule. Upstream dropped it as a copy of a principle its router loads in every session, which doesn't load here.
- A numbered list in the reply, such as findings, still takes the short answers `3`, `skip 3`, and `a, skip 3`, and `?` still asks for the current step and open items. Upstream's answers line dropped them with session-wide numbers, but its reply-shape still numbers a list the reader might answer by number, so the short forms keep a target.
- Upstream's turn block, the JSON comment its hooks parse at the end of each reply, and its tower are left out, since they feed hooks and a T3 setup this library doesn't ship.

`agents/openai.yaml`, `references/setup.md`, the `scripts/` directory, and this record are locally maintained.
