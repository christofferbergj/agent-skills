## Local adaptations to preserve

The wording is first-party. These are the principles taken from the source and the deliberate departures.

Adopted principles:

- At most three lettered options, `a` recommended, as the turn's only question, offered only where the user must act, after a question, or while only external work remains.
- `a` names every push, post, or issue it creates and changes no PR or issue state the user didn't ask for.
- The agent does what a CLI, Executor, an MCP server, or computer control can do; waiting work offers independent work or a watch; filler and options passed over twice drop out.
- Items keep fixed numbers, an option names each item it cites, a summary or handoff keeps each number with its name, and short answers such as `3`, `skip 3`, and `?` work without option lines.
- A SessionStart hook loads the rules into every top-level session in both hosts, including resumes and compactions. Both hosts' hook documentation gives native subagents their own SubagentStart event, so they skip the rules; on 2026-10-20 a fresh T3 Code Claude session received the installed hook's rules and recognized the delegated-task exemption, and a fresh T3 Codex session did the same once the hook was trusted at the user's request.

Departures:

- Only the next-step and Done endings are taken here. Reply-shape's Status, Changed, Needs you, Details, decision card, and writing rules live in /reply-shape, whose own record tracks them.
- Oliver's router stops become a list of points only the user can pass, beside /pstack-principle-never-block-on-the-human, which owns working on without asking.
- A handoff table names the usual next stage in this library's flows.
- After an answer to a question or a read-only request, options appear only when a follow-up needs the user's choice, and the turn otherwise ends with Done. Oliver's rules end every answer with `Next`, which padded answers with options nobody needed.
- A turn that ends while something the agent started will wake it, such as its own subagent, ends with one plain line of what it will do next. Oliver's rules have the agent wait for its subagent but give no ending for a turn that stops meanwhile, so agents filled it with a lone `a` that read as a choice the user had to make.
- The hook is TypeScript run by Node, reads an installed reply skill's `SKILL.md` up to its setup pointer, this one by default and /reply-shape in a second entry, names the skill from its frontmatter, and warns at 8,000 characters to stay under both hosts' per-hook context caps.
- The hook skips T3 Code's delegated tasks through the same state-database lookup as Oliver's, read through Node's built-in SQLite and failing open, but without his `Reply rules: on` opt-in, which no workflow here uses. The rules and /pstack-swarm's briefs still tell delegated tasks elsewhere to report without options.

`agents/openai.yaml`, `references/setup.md`, the `scripts/` directory, and this record are locally maintained.
