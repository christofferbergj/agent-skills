## Local adaptations to preserve

The wording is first-party. These are the principles taken from the source and the deliberate departures.

Adopted principles:

- The other vendor's model reviews what the current one wrote: Codex from Claude, Claude Opus from Codex.
- Round 1 runs both models in parallel, apart from the small-diff tier below, and the coordinator verifies every finding by rerunning or rereading its proof before acting, adds none of its own, and merges findings by root cause with who raised each.
- Blocker, Cleanup, and Optional severities, with a fix, follow-up, or skip call per finding.
- One go runs the whole loop. Later rounds review only the delta, with only the counterpart, and are skipped when every fix was local and its checks pass.
- Three rounds at most; a repeated class of finding stops the loop for a premise check; an autonomous run puts open findings at the top of the PR description.
- Reviewers prove each finding: behavior with a run against the real code, a documented rule, requirement, or doc, prompt, or plan text with the quoted lines, and a test gap with a passing mutant of a changed line. A reviewer that cannot run a proof names its command and marks the finding unproven, repros stay under a fresh `mktemp -d`, the coordinator drops what nothing proves, and no findings is a valid round.
- Plans and specs are reviewable targets, and a plan finding is shown by probing the current tree or running a prototype.
- The packet can be scoped to a user-named file set and can keep a left-out file central to the change, and later rounds rebuild it with round 1's options.
- In T3 Code the counterpart is a tracked child task with an explicit model and effort, launched read-only in plan mode.
- After each set of fixes, the loop reads how far the change grew past its size before review and cuts added code that no fixed finding needs.
- Reviewers name each finding's class, the kind of mistake with every other place the change makes it, and each fix covers the whole class.
- Later rounds receive the settled findings, dropped, skipped, or follow-up, with their reasons, and a settled finding stays settled.
- When the intent asks for a minimal change, a part of the diff the intent still meets without is a Cleanup, shown by the checks passing with it removed.
- Reviewers label a finding Pre-existing when the change did not cause, newly reach, or worsen it, and the coordinator treats it as context.
- A convention finding whose only fix needs a cast or a lint suppression is a follow-up rather than a fix, and a cheaper fix is applied as usual.
- The counterpart's brief is the whole review: it loads no review skill, and it carries upstream's shared lenses, tracing with real inputs, a second run, and every caller of a shared helper, a claim check, and a duplicate search outside the diff, by naming /thermo-nuclear-review's rubric and pasting /code-review's Standards and Spec checks, where those lenses now live.
- For code, the counterpart rates the whole change 1-10 with what cost the most: the worst finding sets the band, scope, fit, test proof, and readability pick its half, and the rating changes no verdict or severity. The round takes the counterpart's rating, moved to the worst kept finding's band when a finding it rests on was dropped, and the report and the coordinator's merge card show it beside the change's size.
- After a Clean round, the change is proved to work at that head before the PR is offered, unless that proof already ran there. Upstream recommends its verify-work skill as the next step; here /principle-prove-it-works is work the agent does anyway, so it runs rather than being recommended.

Departures:

- The same-model pass is /code-review's Standards and Spec axes plus a correctness and security critic on /thermo-nuclear-review's rubric, not a second generic reviewer with a byte-identical prompt. Each rubric keeps its one owner, and bugs get both models' review. Thermos's maintainability rubric stays a manual /thermos audit, because its presumptive structural blockers would become unrequested refactors in an automatic fix loop (user decision, 2026-10-20). The first round 1 in this shape, on the change that introduced it, ran Codex at `xhigh` beside the two /code-review axes and the correctness critic: Codex found nothing, the Claude reviewers raised nine verified Cleanup or Optional findings, all fixed without a delta round, and three suggestions were skipped with reasons.
- When Codex is the counterpart and the diff changes code that runs, round 1 adds a second Codex task, the Codex correctness pass, on /thermo-nuclear-review's rubric. Codex raised most of the verified Blockers in a count of the user's loops, and the user favors Codex usage and review quality over saving usage (ADR 0004, 2026-10-25). The same-model correctness critic stays while that revision's trial runs.
- A same-model /thermo-nuclear-review pass from earlier in the change, such as the correctness reviewer of a /thermos run the user named, stands in for the correctness critic when the only commits since fix that review's findings and a counterpart pass runs. Reason: on 2026-10-28 a Pstack run named /thermos, whose correctness reviewer is the same rubric on the same model, so running both spends about 100k tokens on a duplicate pass. The fixed lines still get the counterpart's review and, for runtime code, the Codex correctness pass.
- Effort is explicit and scales with scope: both vendors run full reviews at `xhigh` and delta reviews at `high`, and GPT models never run above `xhigh`. The source pins Claude at `high` and Codex at `gpt-6.1-terra` `max` for every round, now in its shared t3-delegation Reviewers table, and runs a same-provider reviewer as a T3 child when its model or effort differs from the session's; /swarm's execution contract owns counterpart model and effort resolution here, and same-model critics inherit the session's settings.
- The loop is the final review of /implement, /implement-spec, and Pstack's implementation playbooks, through a library-wide adaptation. The source pairs it with a verify-work skill, drops this provider's reviewer from round 1 when verify-work reviews the same diff, and stops calling a capped autonomous run unverified because verify-work re-checks later fixes. Here a pass is skipped only when equivalent evidence covers the head or the small-diff tier applies, and a capped autonomous run is still reported unverified, since no later review step re-checks it.
- `scripts/packet.ts` writes only the packet: pinned revisions, a working-tree snapshot commit, the kept files' size, and the left-out lockfiles, binaries, and generated or vendored files. Upstream's `packet.sh` also writes one prompt every reviewer gets, under the repository's `.review-loop/`, and packs a PR's description and a plan; here the passes take different rubrics by the same-model departure, so the coordinator fills the brief for each pass with the intent and plan path. Packets live in a temporary directory: plan-mode T3 children of both vendors read it there, and a route that cannot, such as the restricted Claude CLI, gets the packet pasted into its brief.
- `scripts/packet.ts` prints its JSON on one line, and step 1 says to read it whole. Reason: in a 2026-11-04 retrospective, about ten runs piped the pretty-printed output through `tail` or `head`, lost the packet path, and built a second packet.
- Outside T3 Code, /swarm's other routes keep the loop working: the bounded CLI wrapper, then a labeled same-model critic.
- A small diff gets only the counterpart in round 1, unless the user asks for the full round or the counterpart fails: `scripts/packet.ts` reports `tier: small` for at most two files and under 50 changed lines with no auth, payment, data-access, config, env, or dependency path. Reason: in a 2026-11-02 analysis of the owner's threads, small fixes drew three or more review passes, once from the loop alone and otherwise with a review the owner added, while the owner asked to keep the cross-model pass. The threshold is the fan-out skip in Addy Osmani's `/ship` command, taken as an idea; nothing from his repository is tracked.
- Oliver's shared chat format, lens skills (`coding-standards`, `grounding`, `taste`), shared review lenses, and `verify-work`, `autopilot`, `build`, `architect`, and `open-pr` handoffs map to /code-review, /principles, the brief's Code line, /principle-prove-it-works, /pr, and /principle-attack-the-premise. The merge gate and verdict recording, Franklin and Linear specifics, and reply layout are excluded.
- Only the counterpart's Code pass rates the change, where upstream hands every reviewer the same rating lens and takes the lowest: here the same-model passes run /code-review and /thermo-nuclear-review, whose rubrics hold no rating, and the Codex correctness pass sees only correctness. Upstream records the rating with `verdicts.py` for its ship gate; the verdict recording stays excluded, and the size comes from the packet.
- Upstream's Notes line, which has a skill read the user's own steps from `~/.local/state/addystack/notes/<skill name>.md`, is left out. Reason: this library has no per-user notes layer, so a user's change goes into the skill itself.

`agents/openai.yaml`, `references/reviewer-brief.md`, the `scripts/` directory, and this record are locally maintained.
