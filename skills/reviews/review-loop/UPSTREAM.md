## Local adaptations to preserve

The wording is first-party. These are the principles taken from the source and the deliberate departures.

Adopted principles:

- The other vendor's model reviews what the current one wrote: Codex from Claude, Claude Opus from Codex.
- Round 1 runs both models in parallel, and the coordinator verifies every finding against the code before acting, adds none of its own, and merges findings by root cause with who raised each.
- Blocker, Cleanup, and Optional severities, with a fix, follow-up, or skip call per finding.
- One go runs the whole loop. Later rounds review only the delta, with only the counterpart, and are skipped when every fix was local and its checks pass.
- Three rounds at most; a repeated class of finding stops the loop for a premise check; an autonomous run puts open findings at the top of the PR description.
- Plans and specs are reviewable targets.
- In T3 Code the counterpart is a tracked child task with an explicit model and effort, launched read-only in plan mode.
- After each set of fixes, the loop reads how far the change grew past its size before review and cuts added code that no fixed finding needs.
- Reviewers name each finding's class, the kind of mistake with every other place the change makes it, and each fix covers the whole class.
- Later rounds receive the settled findings, dropped, skipped, or follow-up, with their reasons, and a settled finding stays settled.
- Reviewers label a finding Pre-existing when the change did not cause, newly reach, or worsen it, and the coordinator treats it as context.
- The counterpart's brief is the whole review: it loads no review skill, traces each changed path with real inputs and a second run, checks every caller of a shared helper, checks the change's claims in its PR description, docs, and comments, and searches outside the diff for code that already does what a new helper does.
- A Clean round offers proving the change works at that head before delivering the PR, leaving out a step that already ran there.

Departures:

- The same-model pass is /code-review's Standards and Spec axes plus a correctness and security critic on /thermo-nuclear-review's rubric, not a second generic reviewer with a byte-identical prompt. Each rubric keeps its one owner, and bugs get both models' review. Thermos's maintainability rubric stays a manual /thermos audit, because its presumptive structural blockers would become unrequested refactors in an automatic fix loop (user decision, 2026-10-20). The first round 1 in this shape, on the change that introduced it, ran Codex at `xhigh` beside the two /code-review axes and the correctness critic: Codex found nothing, the Claude reviewers raised nine verified Cleanup or Optional findings, all fixed without a delta round, and three suggestions were skipped with reasons.
- When Codex is the counterpart and the diff changes code that runs, round 1 adds a second Codex task, the Codex correctness pass, on /thermo-nuclear-review's rubric. Codex raised most of the verified Blockers in a count of the user's loops, and the user favors Codex usage and review quality over saving usage (ADR 0004, 2026-10-25). The same-model correctness critic stays while that revision's trial runs.
- A same-model /thermo-nuclear-review pass from earlier in the change, such as a /thermos run the user named, stands in for the correctness critic when the only commits since fix that review's findings and a counterpart pass runs. Reason: on 2026-10-28 a Pstack run named /thermos, whose correctness reviewer is the same rubric on the same model, so running both spends about 100k tokens on a duplicate pass. The fixed lines still get the counterpart's review and, for runtime code, the Codex correctness pass.
- Effort is explicit and scales with scope: both vendors run full reviews at `xhigh` and delta reviews at `high`, and GPT models never run above `xhigh`. The source pins Claude at `high` and Codex at `gpt-6.1-terra` `max` for every round, and runs a same-provider reviewer as a T3 child when its model or effort differs from the session's; /swarm's execution contract owns counterpart model and effort resolution here, and same-model critics inherit the session's settings.
- The loop is the final review of /implement, /implement-spec, and Pstack's implementation playbooks, through a library-wide adaptation. The source pairs it with a verify-work skill, drops this provider's reviewer from round 1 when verify-work reviews the same diff, and stops calling a capped autonomous run unverified because verify-work re-checks later fixes. Here a pass is skipped only when equivalent evidence covers the head, and a capped autonomous run is still reported unverified, since no later review step re-checks it.
- A script builds the packet with pinned revisions, a working-tree snapshot commit, and excluded lockfiles, binaries, and generated or vendored files. Packets live in a temporary directory: plan-mode T3 children of both vendors read it there, and a route that cannot, such as the restricted Claude CLI, gets the packet pasted into its brief.
- The size comes from the packet's `git apply --stat`. The source runs `git diff --shortstat` after `git add -N` on untracked files; the packet already pins the revisions, snapshots working changes without touching the index, and leaves out lockfiles and generated files.
- A plan review names a risk only with the code path or observed behavior that shows it, and turns an open question a run could settle into a prototype rather than a finding; the coordinator drops a plan risk that nothing cited supports. Pstack's guide argues that adversarial review of abstract plans invents theoretical risks ([ADR 0005](../../../docs/adr/0005-plan-through-code-by-default.md)).
- Outside T3 Code, /swarm's other routes keep the loop working: the bounded CLI wrapper, then a labeled same-model critic.
- Oliver's shared chat format, lens skills (`coding-standards`, `grounding`, `taste`), shared review lenses, and `verify-work`, `autopilot`, `build`, `architect`, and `open-pr` handoffs map to /code-review, /principles, the brief's Code line, /principle-prove-it-works, /pr, and /principle-attack-the-premise. The merge gate and verdict recording, Franklin and Linear specifics, and reply layout are excluded.

`agents/openai.yaml`, `references/reviewer-brief.md`, the `scripts/` directory, and this record are locally maintained.

It dispatched Claude Opus 5.5 at `xhigh` as a T3 plan-mode child beside three native Codex critics, and T3's thread records confirm all four. Every reviewer reported Clean on a correct change. Its notes on delta-round refreshes and the PR handoff clarified steps 5 and 4. A second Codex-led trial gave the loop a committed implementation with two planted defects: a trailing window that dropped the current page, and a zero width returned silently instead of rejected. Round 1 had Claude Opus at `xhigh` plus three native Codex critics; every reviewer raised the width defect, and Claude, Spec, and Correctness raised the trailing window. Codex verified and fixed three findings in separate commits, and round 2, a Claude Opus `high` delta review in a new T3 task, came back Clean. An independent check of the fixed function confirmed both defects gone. That trial's notes clarified same-model effort inheritance, the Claude plan-mode plan file, and axis-separate reports.
