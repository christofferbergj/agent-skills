## Local adaptations to preserve

- The [library-wide adaptations](../../agents/maintain-skills/references/ADAPTATION.md#library-wide-adaptations) apply; this list holds only this skill's own divergences.
- The description names both branches, coordinated caller migration and deletion or staged coexistence, instead of upstream's internal-API trigger. Reason: /principles selects principles by description, and the owner's staged branch would otherwise contradict upstream's "instead of preserving compatibility layers". This departs from the library-wide rule that principle descriptions keep upstream's triggers, by the owner's answer on #127.
- Own the choice between coordinated internal migration and justified expand-contract, including caller inventory, real compatibility obligations, bounded migration tickets, phase checks, dependent-work gates, and final acceptance. The description and body are rewritten as ordered steps for that choice. Reason: the [library architecture](../../../docs/architecture.md) makes this skill the migration-strategy owner that both suites' workflow owners defer to, so it must also cover the external-compatibility case upstream leaves out of scope. Step 3 says a refactor keeps the Refactoring playbook's no-shims rule, so expand-contract never overrides upstream's playbook, by the owner's answer on #127.
- Keep explicit caller inventory, deletion, temporary-adapter and test-migration rules in this callable dependency, with its external-compatibility applicability limits. Upstream cut the caller-inventory, deletion, and time-boxed-adapter rules as marginal in `99743e9`; they stay because callers invoke this skill for exactly those rules.
