## Local adaptations to preserve

The wording is first-party, and `scripts/project.py` is ported with the changes below. These are the principles taken from the source and the deliberate departures.

Adopted principles:

- The coordinator runs the project and never the code, so its thread stays free for the user. Every change goes to a worker, a T3 child task in its own worktree, and every build, test, verification, and probe to a worker or a subthread; the coordinator checks each claim against the diff and the PR's live state, and sends a claim that needs running to a verifier subthread.
- One pinned `◆ <project>` thread is the only place the user talks to. Its memory is a project folder holding `project.md`, edited through `project.py`, and the standing rules, read first on every wake and after compaction. A rule the user overrides is rewritten in place, so the file holds one current rule.
- Each unit has a proof before it starts, and among units that share one brief a pilot proves the brief before its siblings start. A unit waits on another branch only for what it can't build or check on today's base. A research brief leaves the answer to the worker, marking any guess a hypothesis to refute.
- Two slots bound the workers that build at once, and a task that finishes an open PR goes ahead of queued units. Every task whose inputs exist starts now, held back only by a shared resource, machine load, or a pending fix that will change the head it checks, and a task that only reads, reviews code, or drives an app without building takes no slot.
- Each launch is checked for a start within about two minutes, with `overdue` and `unknown` states, because nothing wakes the coordinator when a child starts.
- More work for a finished worker or subthread goes to its own thread, which keeps its worktree, branch, and conversation, only when the send brings it up to date: its brief still holds and the send names every decision since; otherwise a fresh one starts with the consolidated scope. On 2026-10-31 a Claude child recalled its first brief after such a send.
- Each wake handles the user's message, worker results, pending questions, and PR watch events. The coordinator owns every watch and hands each event to the PR's owner. An hourly heartbeat finds stuck workers, which are cancelled, waited out, and retried by cause in their own threads, and dropped after two retries.
- The coordinator answers what the plan, its decisions, the standing rules, or a probe subthread's report settles, and brings the user one real call per reply, ordered stuck runs, calls, then Do items, showing the next card in the reply that sends an answer.
- A merge is offered only once the PR's owner reports it merge-ready, and goes to that owner with the user's go quoted in their words.
- The close runs an integrated check that merges every open branch onto trunk in a fresh worktree, gives every worker a final state, clears every timer and watch, and unpins the thread.
- The coordinator runs where its units build, since worktrees, wakes, and PR watches stay on one machine, and the machine is picked by what the units need: a macOS machine when any unit needs macOS, otherwise one whose project list holds the repository and whose memory fits the units, preferring a machine other than the user's laptop. On the wrong machine it offers starting there, launching a thread that carries everything the chat agreed. A worker on another machine is report-only, is read with `t3_thread_read` and its `environmentId` because its end and questions wake no one here, and is settled after reading.

Departures:

- The project folder is `~/.local/state/coordinator/<project>/`, and the Standing rules convention and the brief's Scope and Context fields from upstream's `orchestrate` brief live in this skill, since the library ships no `orchestrate` skill. The brief leaves out that brief's Acceptance, Verify, and Timebox fields, because the unit's proof and the worker's /pstack-mode playbook cover them.
- Delegation follows /swarm's T3 route and model roles instead of upstream's `t3-delegation.md` and its Roles table. The report is the route's short message naming a report file, without upstream's numbered report block, its show-me-your-work calls item, or its `Project:` turn block. Each task in a worker's thread writes its own numbered report file, where upstream's random suffix let a later task in the same thread overwrite the first report.
- Workers build through /pstack-mode's playbooks, ending at a draft PR through its Opening a PR playbook, whose final review is /review-loop, unless a standing rule names another flow. Upstream runs its own router flow and autopilot.
- PR maintenance starts at a worker's code-ready result, where upstream watched a PR as soon as it opened, because /pstack-mode's Opening a PR playbook holds babysitting until the stack is built. Each later watch event gets one Babysit pass: the owner works /pstack-mode's Babysit playbook in `drive` mode as an Autopilot owner does, rebasing its own branch, reads status once instead of polling, since the coordinator keeps the watch, and pushes one wave. Babysit has no one-pass mode of its own. A merge is the user's call unless a standing rule grants it, offered as a card listing each PR in merge order, and landed by the owner through /pstack-mode's Shipping playbook. Upstream's per-repository trust values, its `merge-gate.py` hook, and `scripts/stack.sh where` are left out, because this library makes a merge a point only the user can pass. Upstream's coordinator runs the merge line and readies each draft itself, because its hook takes a go only from the user's own prompt in the merging transcript; here the owner lands the PR, and Shipping marks a draft ready right before its merge.
- A worker returns a call as a question, problem, pick, and evidence, and the coordinator shows it as a decision card with a progress strip. The card's parts and the list of real calls are written out in the skill, because /reply-shape and /next-options are user-invoked and load only through their opt-in hook; /reply-shape lays the card out when active. Upstream's workers write the card themselves, and its cards carry a turn block for its tower. With an empty queue the coordinator posts a status line, and goes to the close or replans once nothing runs, where upstream ends on `done`.
- Upstream's `Mode:` and `Worker of:` brief lines, its `Project:` turn block, and the routine-stop and tower hooks that read them are left out, since this library ships neither upstream's router modes nor those hooks. /next-options' session hook already skips T3 delegated tasks.
- Links run one way: a coordinator reaches only the machines its own T3 Code server lists in `t3_environment_links`, and this user's one link goes from their Linux server to their Mac, so `references/across-machines.md` checks the link before offering a move and a coordinator on the Mac runs every unit there. Upstream assumes each machine reaches the other.
- A worker on another machine starts through /swarm's T3 route as a `t3_thread_launch` thread, and returns its report in its final message, read with `t3_thread_read`. Upstream starts a `delegate_task` child in that machine's root checkout, queues workers behind it with a `Waits on: <machine> checkout` line, and reads a report file with `ssh <machine> cat`; their Linux server cannot ssh into the Mac, and /swarm's record gives the launch's reasons.
- Computer use joins upstream's list of macOS needs, but when it is a unit's only macOS need and this machine links to a reachable Mac, the coordinator stays and runs that check as a report-only worker there, since /swarm's Computer Use route already reaches a linked Mac and the user's threads run on their Linux server, while the Mac can sleep.
- The moved coordinator's launch message leaves out upstream's `Mode:` line, under the departure above, and the project folder stays at `~/.local/state/coordinator/<project>/` on whichever machine runs it, where upstream's sat under `~/.local/state/orchestrate/`.
- Upstream's `references/workflow.md`, Oliver's builder workflow, is left out; this library's architecture document and /pstack-mode own the equivalent routing.
- A subthread, the verifier or probe no worker owns, gets its own Workers row and a report-only brief with role `test` or `research` and the `swarm-workers` target, where upstream starts it like a worker, so it doesn't inherit the worker brief's branch ownership and draft PR, and slots, startup, the heartbeat, and the close count it.
- A worker is stuck only when its thread stopped growing too, where upstream judged a worker with a branch by commits and PR activity alone, which would cancel a builder deep in a long review between commits. A startup error is retried at once, where upstream recorded it as the worker's state, which `project.py` refuses.
- Every timer's prompt opens with the user's gate for interval tasks when their instructions set one, because T3 Code replays the interval runs missed while the machine slept, so an unattended two-minute startup timer could fire hundreds of times on wake.
- Without T3 Code's tools the skill stops and points to /pstack-mode's Orchestrate playbook, which runs a program on any host.
- `project.py` drops upstream's `--mode` option and the header's `Mode:` field, adds a Proof column, because step 2 records each unit's proof in Workers and upstream's table had no place for it, and refuses a worker name holding `|`, which upstream wrote unescaped and then could not edit. The Goal section is edited by hand like the close's Result, since no command edits its follow-ups. Its tests sit under `scripts/tests/`, where `pnpm check` discovers them, and use `tempfile.TemporaryDirectory` like the library's other suites.
- The invocation mode matches upstream's model-invoked skill, so a heartbeat, a worker's completion, or a compaction reloads it in a coordinator thread.

Decide upstream changes to `coordinator/` by the principle-derived rules. Review changes to upstream's `orchestrate/SKILL.md` here only for its brief and Standing rules convention; /swarm's record reviews it and `shared/t3-delegation.md` for the T3 route.
