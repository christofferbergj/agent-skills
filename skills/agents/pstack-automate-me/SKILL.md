# Automate me

1. Locate an existing personal mode and its agreed source repository. Installed skill snapshots are discovery inputs, not edit targets. Complete when ownership, current behavior, and the last source-edit date are known.
2. Invoke /pstack-recall for recent history across both hosts for this repository, usually two to four weeks for an initial mode or since the last mode edit for an update. Treat corrections, repeated workflows, and explicit preferences as evidence. Complete when candidate patterns have session pointers and uncertain or contradictory patterns are marked.
3. Ask focused questions about preferences that the history cannot establish. Cluster by task family, evidence standard, communication, decisions, and operational limits. Complete when the user has resolved actual choices rather than facts the agent could inspect.
4. Draft or update the personal mode in the agreed source repository. Invoke existing Pstack owners for shared behavior instead of cloning their instructions. Keep organization details, raw quotes, and provider credentials outside published generic rules. Complete when each proposed rule has a trigger, behavior, owner, and observed reason.
5. Prefer structural enforcement for recurring mistakes through /pstack-correct. Present source changes for review and apply only the approved grant. Complete when accepted and rejected proposals are explicit.
6. Validate metadata, links, dependencies, and a realistic task in an isolated example. Report the source path, changes, evidence, and whether a later installation refresh is needed. Complete when the reviewed mode is usable without silently altering other chats or installed copies.
