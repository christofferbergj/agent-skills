## Local adaptations to preserve

Each divergence names the reason under the owner's rule on #113 that keeps it.

- Step 4 checks a panel seat or setting on another vendor against that provider's models in T3 Code or the counterpart's, since the session's spawn tool lists only its own vendor's (reason 1).

- The [library-wide adaptations](../../agents/maintain-skills/references/ADAPTATION.md#library-wide-adaptations) apply; this list holds only this skill's own divergences.
- Writes personal JSON at `~/.config/pstack/config.json`, or `PSTACK_CONFIG`, with one section per host, instead of Cursor's always-applied `pstack-models.mdc` rule, because /swarm's `scripts/target.py`, which both hosts run for every spawn, reads one file and Codex has no always-applied rules; the file therefore applies at once rather than in new sessions. Repository overrides apply only when explicitly configured. Reason 1.
- Detection reads each host's model and effort options, and effort is a separate option, not a slug suffix, as upstream's Claude Code mapping does: the budget becomes the host section's `budget` key that `target.py` applies, and the slug-ladder fallback, upstream's Fable and Gemini slug limits, and its rule that Opus 5.5 always runs its `-fast` slug have no slug to edit. Reason 1.
- Writes only the user's choices, with no `# defaults` marker and no migration of old default values, because the defaults live in /swarm's `target.py`, so a default change reaches the user without a rerun. Reason 1.
- The arena cross-judge pool is not configured here: /arena takes upstream's pool, Opus then Gemini 4 Neon from another vendor than the parent's, through /swarm's routes. Reason 1.
- Keeps credentials in the providers' stores, which the counterpart routes use. Reason 1.
- Step 1 also notes whether the counterpart and Codex Computer Use can run, and step 3 asks for the counterpart reviewer's provider instance, model, full and delta effort, and speed, the Computer Use delegate's settings, and the Codex pace slack, floor, and fallback threshold, which /swarm's routes read. Step 2 drops every saved entry `target.py --help` doesn't list, apart from the schema version and source location, beside upstream's retired roles, because those keys are local and the helper ignores unlisted ones silently. Reason 1.
- Step 8 asks the user to type /create-formal-verification-skill rather than invoking it, because that skill is user-invoked and Claude Code refuses it when an agent loads it. Reasons 1 and 3.
