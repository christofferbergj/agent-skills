## Local adaptations to preserve

- The [library-wide adaptations](../../agents/maintain-skills/references/ADAPTATION.md#library-wide-adaptations) apply; this list holds only this skill's own divergences.
- Configure one shared project contract for both hosts. Reuse existing domain/tracker/label choices and legacy artifact locations, which stay authoritative unless the user accepts upstream's offered `git mv` to the `GLOSSARY` name, which the skill offers only for a legacy file /domain-modeling resolves as the vocabulary or context map; personal Pstack model-role setup remains optional. Use the GitLab API relation `is_blocked_by` when identifying native blockers; `/blocked_by` remains the quick action.
- Instruction files: upstream never creates `AGENTS.md` beside `CLAUDE.md` (or the reverse). Locally the existing source stays authoritative, and the smallest host-native pointer or documented symlink lets the other host reach it. Codex reads `AGENTS.md` and configured fallback names, never `CLAUDE.md` by default. Claude Code 2.1.277 and later reads `AGENTS.md` only when no `CLAUDE.md` exists, and some sessions read `CLAUDE.md` alone. A `CLAUDE.md`-only repository therefore still needs the pointer for Codex.
- When neither instruction file exists, recommend `AGENTS.md` and create it once the user agrees, where upstream asks which one to create and doesn't pick. Reason: both hosts now read `AGENTS.md`, so it needs no pointer (owner decision, 2026-10-25).
- `domain.md` is restructured as a role-based contract: it names authoritative artifacts by role, respects legacy `CONTEXT.md`/`context.md`/`domain.md` files, delegates updates to /domain-modeling and architectural vocabulary to /codebase-design, and keeps canonical edits with the coordinator. Upstream's single- and multi-context file trees are delegated to /domain-modeling, which holds the same layouts. Upstream's read list, silent-absence rule, glossary-vocabulary rule, and ADR-conflict example are kept in its wording.
- GitHub and GitLab notes preflight the CLI and pass multiline text through UTF-8 body files or JSON API input instead of heredocs and inline `--body`, so issue text never passes through shell quoting. GitLab's interactive `--description -` editor option is dropped because agents cannot drive an editor. Publishing waits for the task's grant.
- GitLab's external-MR list keeps `glab mr list -F json`, where upstream (ed0de59) changed it to `-O json`. Reason: glab's `mr list` reference gives `-F, --output` and `-o, --order` and has no `-O`; `-O, --output` belongs to `glab issue list`, the command upstream's report (mattpocock/skills#1143) tested.
