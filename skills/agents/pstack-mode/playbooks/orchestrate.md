# Orchestrate

Own the standing program, briefs, state, and verification frontier.

1. Frame the program's countable done predicate, tracks, units, dependencies, authority, and wall-clock budget. If one agent can finish inside the session's budget, use Autonomous run directly. Complete when program-level machinery is justified by actual scale.
2. Create a task-scoped runtime store outside installed skill files. Use `bun scripts/orch/orch.ts --store <store> init` from this skill directory, then its `--help` for unit, ledger, inbox, gate, frontier, and standing-order operations. Frontier heads come from GitHub's immutable PR metadata. If `origin/HEAD` is absent, discover the actual default branch through repository/forge metadata and pass `--trunk <branch>`; never guess `main`. The retained Origin option reports unavailable until its immutable head schema is verified; use supported native tools for another forge. Keep canonical plain files inspectable. Complete when state survives a coordinator restart and each shared file has one writer.
3. Pilot one representative unit before scaling. Each worker brief includes goal, scope, inputs, exact revision, allowed writes, verification command, output contract, timebox, and report path. Use /pstack-swarm's host contract and separate worktrees. Complete when pilot evidence validates the brief and acceptance mechanism.
4. Maintain a rolling window of useful work within host capacity. Relay upstream context into dependent briefs, collect terminal reports, and spot-audit brief quality. A role can outlive a failed agent; replacements receive a consolidated brief and current artifacts. Complete each wave when every spawned worker is represented in durable state.
5. Verify independently on exact heads, store evidence keyed by unit and revision, and drive the lowest ready dependency through its authorized lifecycle. A new head needs a matching verdict. Gate changes need independent evidence and the coordinator's decision; forge protections remain mandatory. Complete when every accepted unit has a current verdict and every human gate is parked explicitly.
6. Audit liveness through actual processes, native task status, repository state, and outputs rather than transcript mtime or summaries alone. Retry a recoverable unit at most twice, reducing scope or changing the method as evidence warrants; then abandon or replan explicitly. Bound coordinator infrastructure retries too. Complete each checkpoint when progress, failures, and the next frontier are durable.
7. On a pause, propagate a stop to every writer and follow Pause safely. On completion or budget expiry, reconcile all job states, audit the trail through /pstack-show-me-your-work, and preserve the store. Complete when the done predicate is proved or unfinished work has an exact handoff.

Return counts from stored state, tracks, PRs and revisions, verdicts, abandoned work, parked decisions, and store/trail paths. Resume from artifacts and current forge state, not obsolete agent IDs.
