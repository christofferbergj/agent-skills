# Refactoring

Own the behavior contract. Structure changes; behavior stays fixed.

If the cleanup reveals a missing feature or a real bug, split it out and ship the structural change first against the pinned contract. A redesign is allowed, but name it and route to Feature. Large or cross-cutting structural work belongs to /pstack-figure-it-out.

1. Invoke /codebase-design for interface and seam vocabulary and /domain-modeling for the configured artifacts. Identify observable contracts, callers, state ownership, and existing tests with /pstack-how. Pin the behavior contract first: write a characterization test, snapshot, or equivalence harness that captures current behavior before any structure moves. Type check and lint are not a pin. Complete when the behavior to preserve is pinned and the structural problem is explicit.
2. Name the structure the code is missing per /pstack-principle-model-the-domain, and the target shape as if built today. Boring code stays when the shape is already clear and local; the reshape must delete branches or invalid states, not add indirection. Use /pstack-architect for boundary changes and /pstack-arena when several consequential shapes compete. Preserve approved-interface gates. Complete when the target shape and caller migration are concrete.
3. Subtract before you add (/pstack-principle-subtract-before-you-add): delete dead code, collapse one-caller wrappers, drop redundant validators, and remove orphan references before introducing the new shape. Then move in small behavior-preserving steps, each keeping the pin green, using codemods or scripts where they establish exhaustive coverage. Invoke /pstack-principle-migrate-callers-then-delete-legacy-apis for the migration strategy and gates. Spot-check every rename against the actual files; renames silently miss usages in strings, prose, and back-references. Delegate mechanical edits through /pstack-swarm on your configured refactoring role with a specific scope. Complete when every affected caller and required compatibility obligation is accounted for.
4. Run behavior checks against old and new states on the real artifact, including bugs if byte-identical or bug-compatible behavior was requested. For larger reshapes, run an equivalence check: a script that diffs old-vs-new outputs, a recorded baseline replayed against the new code, or a smoke run on the matching surface. Complete when the preserved contract has evidence and deviations are explicit.
5. Confirm the change is worth keeping. The success measure is reduced reader load (/pstack-principle-minimize-reader-load); if the diff does not lower reader load somewhere, revert it. Complete when the reader-load delta is named.
6. Rebase into small ordered commits: a subtraction commit, then the reshape, then any follow-on cleanup, each green per /pstack-principle-sequence-verifiable-units. Inspect the final structure, review it through /review-loop, and follow Opening a PR when authorized. Complete when obsolete paths are removed and the verification applies to the final artifact.

Return the structural change, the pin it held against, the equivalence proof, the reader-load delta, migration coverage, what shipped and what got reverted, and any deliberate deviation. No new behavior.
