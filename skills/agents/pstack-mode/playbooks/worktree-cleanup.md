### Worktree and simulator cleanup

1. Snapshot and audit. Record `df -h /`, then run `python3 scripts/worktree-audit.py --repo <repo-path> --base <pr-base-ref> --activity-index <history.json> --ownership-index <ownership.json>` from this skill's directory (/pstack-principle-build-the-lever). Pass the branch PRs target as `--base`, such as `origin/<branch>`. It reads paths from `git worktree list`, never hand-typed, since a hand-typed `myrepo-worktrees/x` misses one that lives under a host's own worktree directory (/pstack-principle-encode-lessons-in-structure). Build the activity index from /pstack-recall's cross-host history, generated within the last 15 minutes and covering at least four days. Build the ownership index from the host's worktree and thread state, generated within the last 15 minutes, with `repository`, `generatedAt` in Unix seconds, and a `worktrees` array giving each worktree's path, kind, and explicit `active`, `pinned`, and `shared` booleans. The audit is read-only. It classifies each worktree by merge state, local files, Git state, ownership, and recent activity, treats missing history or ownership as unknown, and marks it `hold` with its reasons or `candidate-for-final-inspection`. The history scan is slow, so background it.
2. The bucket is advice, not permission. The pinned and active threads are the real artifact (/pstack-principle-prove-it-works). Get that set from the user or the host's thread list and cross-check every candidate. The lever has marked as removable a worktree the user had pinned, so the pinned set wins.
3. Verify usage before deleting. For every row held for recent activity, or anything you doubt, fan subagents out to read the sessions through /pstack-recall and report whether the thread is pinned or ongoing and which worktrees it touches (/pstack-principle-guard-the-context-window, transcripts are bulk). A pinned thread spawns arena and repro trees into sibling worktrees via background subagents, and those are in use even when their names never appear in the thread list. Pick each subagent's reasoning level and fast or standard speed for the job, per the Subagents section.
4. Pause on irreversible loss. A worktree held for tracked edits has uncommitted work. Show the diff and get a decision first, since removing a clean worktree is recoverable from its branch but uncommitted work is gone. Untracked throwaway is safe to drop, but name the files. Per Autonomy, clean and merged and not-in-use proceeds. Uncommitted work and in-use pause.
5. Prune the confirmed set. Remove a host-managed worktree through the host's worktree API. For any other path, `git worktree remove --force <path>`. If the dir survives on ignored build artifacts, `rm -rf` it, then `git worktree prune`. Branch refs survive, so no commits are lost. Confirm with `df -h /` and re-list.
6. Simulators and other reclaimers. Simulators are usually the next-biggest win. `xcrun simctl --set testing delete all` (XCTestDevices clones), `xcrun simctl delete unavailable`, and `xcrun simctl runtime list` then `runtime delete <id>` for old runtimes. More when needed: Xcode `DerivedData` and `iOS DeviceSupport`, `~/Library/Application Support/Cursor` (`state.vscdb.backup`, and `snapshots/roots/<root>` where a `<root>` named for a folder you opened as a workspace balloons), package caches (pnpm, uv, brew, yarn). Clear only caches the user has not said to keep.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** `df -h /` before and after with space reclaimed, the worktrees pruned, and a one-line reason for each held back (in-use by which thread, or uncommitted work).
