# Hillclimb

Own scientific progress on one metric within an agreed budget. Supervise and review; delegate the attempts.

Core discipline: one change, one measurement, keep or revert. Never stack untested changes, and never claim a win from code inspection (/pstack-principle-prove-it-works).

1. Ground the workload with /pstack-how over the target, name the realistic workload dimensions that can move the result (data size, history, state, concurrency), and select a case that reproduces the user's complaint. If no case reproduces it, fix the repro instead of hillclimbing. Fix one metric, the direction that counts as better, a correctness gate, and a checkable stop predicate that pairs a target with a floor on attempts so a lucky early win can't end the run. Use the user's numbers when given, otherwise agree them. Complete when an improvement cannot be manufactured by doing less work or hiding errors.
2. Build the measurement harness, prove its sensitivity, then freeze it (/pstack-principle-build-the-lever). Confirm the target case reproduces the symptom while easier cases separate as expected. Vet the harness with /pstack-benchmark-checklist before freezing it, and make it print its error count and a count of the work done. Once frozen, one repeatable command emits the metric, sampled enough to clear the noise (median of N, not a single run). Complete when the baseline metric and a green run of the regression gate are recorded before any change.
3. Open the decision log via /pstack-show-me-your-work: a `decision.tsv`, one row per attempt (id, hypothesis, change, before, after, delta, tests, verdict, note), kept out of the tree. Read it before each attempt. Ground each hypothesis in a specific mechanism, not "try memoizing something"; for a perf metric, order hypotheses by the performance mantras in [Perf issue](perf-issue.md) step 2, borrowing only their order. Complete when the hypothesis queue is grounded and the log exists.
4. Loop, one hypothesis per iteration. Hand each change through /pstack-swarm to a subagent on your configured hillclimb role with a tight scope, and review the diff rather than typing it. Fan independent hypotheses to parallel subagents, each in its own worktree. Measure before and after with the frozen harness and run the regression gate. Accept only when the metric moves past noise and the gate stays green; otherwise revert the change in full. One commit per accepted fix, staging only the files you changed (`git add <files>`, never `-A`). Log the row either way. Complete each trial when evidence accepts or rejects the hypothesis.
5. Push past the first plateau. On a stall, pivot category, combine near-misses, re-read the source, or try something more radical before concluding the hill is climbed. Correctness and simplicity outrank the number: revert a win that breaks behavior, and keep a simplification that holds the number. Complete each checkpoint when the best known artifact and evidence are durable.
6. Stop when the predicate is met, the agreed limit is reached, or the remaining ideas are marginal and not worth their cost. Don't relax the predicate to meet it, and don't quit while cheap untried hypotheses remain. If stuck, surface it instead of spinning. Complete when remaining hypotheses and the resumption path are explicit.
7. Follow Opening a PR when authorized, with the accepted commits stacked in the order they landed.

Return the metric and target, baseline to final with the percent delta, iterations run (kept vs reverted), each accepted fix on one line, the `decision.tsv` path, correctness evidence, and the best idea to try next.
