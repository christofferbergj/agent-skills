## Local adaptations to preserve

- The [library-wide adaptations](../../agents/maintain-skills/references/ADAPTATION.md#library-wide-adaptations) apply; this list holds only this skill's own divergences.
- Local-only files: `MAINTENANCE.md`, `VALIDATION.md`, and `suite.json`, the Pstack mapping that `/maintain-skills` reads; `references/plan-template.md`, the plan skeleton upstream keeps inline in its multi-phase-plan playbook, moved out so the playbook's steps stay legible; `scripts/worktree-audit.py` with `scripts/tests/test_worktree_audit.py`, which replace upstream's `scripts/worktree-audit.sh` with a read-only audit over host-neutral activity and ownership indexes instead of Cursor transcripts and sidebar state; `scripts/orch/lock.ts` with `lock.test-helper.ts`, `store-lock.test.ts`, `store-concurrency.test.ts`, `cli-cleanup.test.ts`, and `cli-cleanup.test-helper.ts`, the serialized lock and Store fixes listed below; and `scripts/bootstrap.test.ts` with `scripts/tsconfig.json`, which test and typecheck the immutable-source runtime.
- Cursor mechanics map to these hosts as follows, so later reviews translate new upstream text the same way. `poteto-agent`, `Task` defaults, and fixed model slugs become /pstack-swarm spawns on the roles /pstack-setup configures, with effort and speed set through the host's supported options. `/loop` becomes the host's native loop or scheduling tool, with a durable checkpoint where none exists. `AskQuestion` becomes asking the user. `create-skill` becomes /writing-for-agents. `cursor-team-kit`'s `control-ui` and `control-cli` become the project's verification skill or the host's browser and terminal control tools. `/deslop` becomes a deslop pass with the repository's or host's cleanup tool, when one exists. `agent-transcripts/` becomes /pstack-recall history. Cursor cloud agents and `environment: "cloud"` become the host's cloud execution where it has one. Opening a PR uses `gh` or the repository's established forge CLI instead of the Origin forge, the author's own environment. Babysit, Shipping, and Autopilot-full keep upstream's Origin paths as written, because upstream gates them on `command -v origin`, so they stay inert without that CLI.
- SKILL.md replaces upstream's Principles catalog with /pstack-principles, which holds the selection rules; the Non-negotiables keep upstream's citation rule.
- Session pickup adds that a prior session's authorizations do not carry over, because a resumed transcript's merge, deploy, or message grants were given to another session and the library honors only the user's existing authorization.
- Multi-phase plan sizes live lanes to the PR's surfaces and risks, ten by default for an interaction change, where upstream fixes ten; and a live or perf block with no applicable surface, such as a docs-only PR, may read `Not applicable. <concrete reason>`. Reason: the library scales verification to the task's scope, and `scripts/check-plan.mjs` enforces a declared lane count and a named reason for each omission. The template reads the playbooks from the installed skill rather than `git show origin/main:pstack/...`, because these skills are installed rather than living in the target repository's trunk, and its audit tick needs a `Base ref.` and an `Audit cadence.` box, which the checker requires.
- Worktree cleanup runs `worktree-audit.py`, whose buckets are `hold` with reasons or `candidate-for-final-inspection`, so steps 3 and 4 name its hold reasons instead of upstream's `verify-recent-chat`, `wip:N`, and `scratch:N`. Host-managed worktrees are removed through the host's worktree API before any `git worktree remove --force`.
- Orchestrate passes `--store` to `orch`, takes frontier heads from forge PR metadata, passes `--trunk` when `origin/HEAD` is absent instead of guessing `main`, and adds a Lock recovery section, all for the script changes below.
- Autopilot audit ticks re-read the installed playbooks instead of reading them from trunk, because these skills are installed rather than living in the target repository. The plan template's two rebase boxes defer to the execution playbook's base and topology writer, so a plan run under Autopilot-stack keeps the root as the only rebaser.
- Draft PRs reach merge through an explicit step: Babysit passes `--allow-draft` to the watcher and never marks a draft ready, and Shipping (step 4) and Autopilot-full (step 5) mark a draft ready only right before its own merge under the landing grant. The library-wide authority adaptation opens draft PRs, which GitHub cannot merge and the watcher treats as a merge gate, where upstream opens ready PRs.
- Share phase-specific principle selection with Matt entrypoints through the locally authored /pstack-principles owner. Preserve explicit mode activation and keep suite.json as a source mapping rather than a second selection policy.
- Keep one maintenance engine in `/maintain-skills`; `suite.json` remains this family's data source. Include category/shared files inside upstream skill roots.
- Preserve explicit review and unknown/blocked merge gates, cycle-safe stack traversal, forge-supplied immutable PR heads, active-over-historical PR selection, and verified trunk resolution. Hold an unverified Origin head API instead of substituting local refs.
- Keep polling sleeps, retries, and queued partial sweeps within the configured deadline. In-flight queries finish; this option does not cancel subprocesses.
- Serialize orchestration lock mutations and identify leases independently of PID. Recover legacy PID-only locks and dead mutation guards; an earlier handle cannot release its successor. Force remains an explicit main-lease override.
- Serialize operations admitted through each Store handle, preserving call-order visibility and draining accepted work before close releases the lease.
- Keep a failed close retryable without reopening the store to operations. Retain its release identity until cleanup succeeds and share concurrent close attempts. CLI cleanup failures warn without changing the operation result or hiding its primary error.
- Scope lock ownership to updated cooperating writers on one host. PID reuse or unavailable process probing conservatively blocks automatic guard reclamation.
