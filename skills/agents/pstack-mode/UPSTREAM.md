## Local adaptations to preserve

- The [library-wide adaptations](../../agents/maintain-skills/references/ADAPTATION.md#library-wide-adaptations) apply; this list holds only this skill's own divergences.
- Babysit names the PR with the watcher's `--pr <n>` flag and says it takes no positional argument, because four runs on these hosts passed the number positionally and lost a background run (reason 4).
- Local-only files: `MAINTENANCE.md`, `VALIDATION.md`, and `suite.json`, the Pstack mapping that `/maintain-skills` reads; `scripts/worktree-audit.py` with `scripts/tests/test_worktree_audit.py`, which replace upstream's `scripts/worktree-audit.sh` with a read-only audit over host-neutral activity and ownership indexes instead of Cursor transcripts and sidebar state; and `scripts/bootstrap.test.ts` with `scripts/tsconfig.json`, which test and typecheck the immutable-source runtime. Reason 1.
- Cursor mechanics map to these hosts as follows, so later reviews translate new upstream text the same way. `poteto-agent`, `Task` defaults, and fixed model slugs become /swarm spawns on upstream's roles, which /swarm's `scripts/target.py` resolves and /pstack-setup can override, with effort and speed set through the host's supported options. Model slugs translate through upstream's `docs/harness/claude-code.md` mapping, such as `claude-opus-5-5-xhigh-fast` to `opus xhigh`, and name Claude Code, because Codex roles keep Codex's own model; upstream's Gemini panel seat runs Gemini 4 Neon through /swarm's T3 route to T3 Code's Antigravity provider, with Codex as its fallback. `/loop` becomes the host's native loop or scheduling tool, with a durable checkpoint where none exists. `AskQuestion` becomes asking the user. `create-skill` becomes /writing-for-agents. `cursor-team-kit`'s `control-ui` and `control-cli` become the project's verification skill or the host's browser and terminal control tools. `/deslop` becomes a deslop pass with the repository's or host's cleanup tool, when one exists. `agent-transcripts/` becomes /recall history. The agent store and the Project store become a task-scoped directory outside the installed skill files. Cursor cloud agents and `environment: "cloud"` become the host's cloud execution where it has one. Opening a PR uses `gh` or the repository's established forge CLI instead of the Origin forge, the author's own environment. Babysit, Shipping, and Autopilot-full keep upstream's Origin paths as written, because upstream gates them on `command -v origin`, so they stay inert without that CLI. Reason 1.
- SKILL.md takes every spawn's speed from /swarm's target and leaves out upstream's "Opus 5.5 always runs its `-fast` slug", because upstream's Claude Code mapping drops fast mode and Codex sets its own speed (owner decision, 2026-10-27: Codex speed ahead of cost, Claude never fast). A cross-vendor critic or Computer Use check also keeps the model and effort the target resolves. Reason 1.
- SKILL.md leaves out upstream's rule that a setup file without a `# defaults: 3` line (formerly `# defaults: 2`) comes from an older setup and prompts a rerun of `/setup-pstack`. Reason: /pstack-setup writes only the user's overrides to `~/.config/pstack/config.json`, /swarm's `scripts/target.py` resolves every default at run time, and /pstack-setup step 2 already drops retired roles, so no local file pins an old default. Reason 1.
- SKILL.md's first-message trigger opens each PR description's `## Summary` with the user's goal, where upstream opens a `## Why` section, because /pr owns the PR description's shape and has no Why section. Reason 2.
- SKILL.md's triggers add a council consult after the prototype trigger, and that line holds its conditions. Upstream has no such trigger and no council. Reason 3: the council consult adaptation, which ADR 0001's 2026-11-26 revision records with the counts behind it. The round is single, unscored, and leaves no PR section, where /council repeats until every member is satisfied and reports scores, because a fork has no fix to re-review and no diff to score. The Subagents section adds /council to the routed skills that choose their own reviewers, so its one member per model maker stands against the mode's panel seats.
- The Orchestrate playbook stays, where upstream deleted it in `2f87c85` and routes a whole program to /figure-it-out. Owner's answer on #113, reason 1: /coordinator sends a program to it on hosts without T3 Code, as ADR 0006 and `docs/architecture.md` record. SKILL.md's Playbooks section keeps it in the list with one routing sentence, and /pstack-help keeps its close call. It no longer receives upstream fixes; its text is upstream's at `bf0c7cd` with the host translations below.
- Orchestrate's "Call no scripts" reads "Call no orchestration scripts", because /swarm's execution contract runs `scripts/target.py` before each spawn and `scripts/review.py` on its CLI route; upstream's ban targets the deleted `orch` runtime. Reason 1.
- SKILL.md replaces upstream's Principles catalog with /principles, which holds the selection rules; the Non-negotiables keep upstream's citation rule. Reasons 2 and 3: the library-wide Pstack adaptation, shared with Matt's owners.
- SKILL.md's Autonomy section pauses for a merge or a message to a person the user has not asked for this session, and drops team chat from the external actions that proceed without asking, where upstream lets team chat proceed and pauses only for customer messages. Owner decision, 2026-11-12: /next-options, which its opt-in SessionStart hook loads in every session, reserves a merge and a message to a person for the user, and the two lists must agree. The sentence stays in SKILL.md instead of pointing to /next-options, because that skill is user-invoked and a session without it could not load the rule. Reason 3.
- Session pickup adds that a prior session's authorizations do not carry over, because a resumed transcript's merge, deploy, or message grants were given to another session and the library honors only the user's existing authorization. Reason 3.
- Worktree cleanup runs `worktree-audit.py`, whose buckets are `hold` with reasons or `candidate-for-final-inspection`, so steps 3 and 4 name its hold reasons instead of upstream's `verify-recent-chat`, `wip:N`, and `scratch:N`. Host-managed worktrees are removed through the host's worktree API before any `git worktree remove --force`. Reason 1.
- Autopilot audit ticks re-read the installed playbooks instead of reading them from trunk, because these skills are installed rather than living in the target repository. Reason 1.
- `worker.md` opens PRs as drafts unless the operator asked for a ready one, where upstream opens every PR ready (reason 3, draft PRs); takes the PR title from the repository's convention (reason 3, the authority adaptation honors the invoking repository's conventions) and the body from /pr (reason 2), where upstream fixes a `type(scope): subject` title, `##` headings, and a 40-line cap; adds a merge the operator has not asked for to the stops (reason 3, user-only points); and counts the steps of a playbook the kickoff names as part of the bar, so the Opening a PR playbook's /review-loop final review is not an added review round (reason 3). Opening a PR makes the same title, body, and draft translations; it keeps `gh pr create --draft` and the repository's forge CLI in place of upstream's `origin pr create --status open`, since Origin's draft flag is unverified (reason 3).
- Draft PRs reach merge through an explicit step: Babysit passes `--allow-draft` to the watcher and never marks a draft ready, and Shipping (step 4) and Autopilot-full (step 5) mark a draft ready only right before its own merge under the landing grant. The library-wide authority adaptation opens draft PRs, which GitHub cannot merge and the watcher treats as a merge gate, where upstream opens ready PRs. Reason 3.
- Opening a PR gives /review-loop, the library-wide final review, its own **Final review** paragraph. A review the user names, such as /thermos, runs as well and passes its evidence to /review-loop, and the reply that posts the PR quotes /review-loop's verdict line with its reviewer counts. Reason: on 2026-10-27 a run told to "do a Thermos review before you open the PR" treated Thermos as the final review, so the Codex pass never ran and its reply showed no gap. Upstream has no final-review sentence here, so every upstream rule in the playbook survives. SKILL.md's triggers add "Before opening a PR", which points to this playbook and its Final review. Reason: on 2026-10-28 a Refactoring run reached "Run **Opening a PR**", wrote the PR through /pr without opening the playbook, and again ran only /thermos. Upstream has no such trigger. Reason 3, /review-loop as the final review.
- Share phase-specific principle selection with Matt entrypoints through the locally authored /principles owner. Preserve explicit mode activation (ADR 0007), and keep suite.json as a source mapping rather than a second selection policy. SKILL.md's spec-graph line names /implement-spec, which runs an accepted ticket graph through these playbooks; upstream has no spec or ticket flow. Reasons 2 and 3.
- Keep one maintenance engine in `/maintain-skills`; `suite.json` remains this family's data source. Include category/shared files inside upstream skill roots. Reason 1, Skills CLI installs.
- The PR watcher preserves explicit review and unknown or blocked merge gates and cycle-safe stack traversal. Reason 4: watcher repairs kept from the 2026-10-16 and 2026-10-17 reviews.
- Keep polling sleeps, retries, and queued partial sweeps within the configured deadline. In-flight queries finish; this option does not cancel subprocesses. Reason 4: repairs of upstream's interval and backoff overshoot, with failing-before tests (2026-10-16 row).
