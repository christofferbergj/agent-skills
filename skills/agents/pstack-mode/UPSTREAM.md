## Local adaptations to preserve

- The [library-wide adaptations](../../agents/maintain-skills/references/ADAPTATION.md#library-wide-adaptations) apply; this list holds only this skill's own divergences.
- Local-only files: `MAINTENANCE.md`, `VALIDATION.md`, and `suite.json`, the Pstack mapping that `/maintain-skills` reads; `references/plan-template.md`, the plan skeleton upstream keeps inline in its multi-phase-plan playbook, moved out so the playbook's steps stay legible; `scripts/worktree-audit.py` with `scripts/tests/test_worktree_audit.py`, which replace upstream's `scripts/worktree-audit.sh` with a read-only audit over host-neutral activity and ownership indexes instead of Cursor transcripts and sidebar state; and `scripts/bootstrap.test.ts` with `scripts/tsconfig.json`, which test and typecheck the immutable-source runtime.
- Cursor mechanics map to these hosts as follows, so later reviews translate new upstream text the same way. `poteto-agent`, `Task` defaults, and fixed model slugs become /swarm spawns on upstream's roles, which /swarm's `scripts/target.py` resolves and /pstack-setup can override, with effort and speed set through the host's supported options. "Your fast code model" is the `fast-code` role. `/loop` becomes the host's native loop or scheduling tool, with a durable checkpoint where none exists. `AskQuestion` becomes asking the user. `create-skill` becomes /writing-for-agents. `cursor-team-kit`'s `control-ui` and `control-cli` become the project's verification skill or the host's browser and terminal control tools. `/deslop` becomes a deslop pass with the repository's or host's cleanup tool, when one exists. `agent-transcripts/` becomes /recall history. The agent store and the Project store become a task-scoped directory outside the installed skill files. Cursor cloud agents and `environment: "cloud"` become the host's cloud execution where it has one. Opening a PR uses `gh` or the repository's established forge CLI instead of the Origin forge, the author's own environment. Babysit, Shipping, and Autopilot-full keep upstream's Origin paths as written, because upstream gates them on `command -v origin`, so they stay inert without that CLI.
- SKILL.md takes every spawn's speed from /swarm's target instead of upstream's fast-mode-only-when-urgent rule: Codex runs in fast mode while its usage stays at or above the configured threshold, 40% by default, and Claude never uses fast mode. Owner decision, 2026-10-27: the user puts speed ahead of cost for Codex, whose usage they don't use up, and keeps Claude's usage for the main agent. A cross-vendor critic or Computer Use check also keeps the model and effort the target resolves. Playbook steps that pick "fast or standard speed for the job, per the Subagents section" keep upstream's wording, and that section's rule decides the pick.
- SKILL.md's first-message trigger opens each PR description's `## Summary` with the user's goal, where upstream opens a `## Why` section, because /pr owns the PR description's shape and has no Why section.
- Orchestrate's "Call no scripts" reads "Call no orchestration scripts", because /swarm's execution contract runs `scripts/target.py` before each spawn and `scripts/review.py` on its CLI route; upstream's ban targets the deleted `orch` runtime.
- The plan template's last merge box takes the execution playbook's merge-or-handoff rule, where upstream's template still has the root append each PR to a base-branch stack, because #986's Autopilot-stack hands verified PRs to the operator and stacks a PR only on one it builds on; drop this once upstream updates its template.
- SKILL.md replaces upstream's Principles catalog with /principles, which holds the selection rules; the Non-negotiables keep upstream's citation rule.
- Session pickup adds that a prior session's authorizations do not carry over, because a resumed transcript's merge, deploy, or message grants were given to another session and the library honors only the user's existing authorization.
- Multi-phase plan sizes live lanes to the PR's surfaces and risks, ten by default for an interaction change, where upstream fixes ten; and a live or perf block with no applicable surface, such as a docs-only PR, may read `Not applicable. <concrete reason>`. Reason: the library scales verification to the task's scope, and `scripts/check-plan.mjs` enforces a declared lane count and a named reason for each omission. The template reads the playbooks from the installed skill rather than `git show origin/main:pstack/...`, because these skills are installed rather than living in the target repository's trunk, and its audit tick needs a `Base ref.` and an `Audit cadence.` box, which the checker requires.
- Worktree cleanup runs `worktree-audit.py`, whose buckets are `hold` with reasons or `candidate-for-final-inspection`, so steps 3 and 4 name its hold reasons instead of upstream's `verify-recent-chat`, `wip:N`, and `scratch:N`. Host-managed worktrees are removed through the host's worktree API before any `git worktree remove --force`.
- Autopilot audit ticks re-read the installed playbooks instead of reading them from trunk, because these skills are installed rather than living in the target repository. The plan template's two rebase boxes name the execution playbook's base, which is the parent PR's branch for a PR that Autopilot-stack stacks, where upstream says current trunk, because Autopilot-stack step 2 rebases a stacked PR onto its parent.
- Draft PRs reach merge through an explicit step: Babysit passes `--allow-draft` to the watcher and never marks a draft ready, and Shipping (step 4) and Autopilot-full (step 5) mark a draft ready only right before its own merge under the landing grant. The library-wide authority adaptation opens draft PRs, which GitHub cannot merge and the watcher treats as a merge gate, where upstream opens ready PRs.
- Opening a PR gives /review-loop, the library-wide final review, its own **Final review** paragraph. A review the user names, such as /thermos, runs as well and passes its evidence to /review-loop, and the reply that posts the PR quotes /review-loop's verdict line with its reviewer counts. Reason: on 2026-10-27 a run told to "do a Thermos review before you open the PR" treated Thermos as the final review, so the Codex pass never ran and its reply showed no gap. Upstream has no final-review sentence here, so every upstream rule in the playbook survives.
- Share phase-specific principle selection with Matt entrypoints through the locally authored /principles owner. Preserve explicit mode activation and keep suite.json as a source mapping rather than a second selection policy.
- Keep one maintenance engine in `/maintain-skills`; `suite.json` remains this family's data source. Include category/shared files inside upstream skill roots.
- The PR watcher preserves explicit review and unknown or blocked merge gates and cycle-safe stack traversal.
- Keep polling sleeps, retries, and queued partial sweeps within the configured deadline. In-flight queries finish; this option does not cancel subprocesses.
