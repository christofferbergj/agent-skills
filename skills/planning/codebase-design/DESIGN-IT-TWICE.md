# Design it twice

Use this pattern for a consequential module interface with materially different viable shapes. In an existing `/pstack-architect` or `/pstack-arena` run, contribute the vocabulary and constraints to that run rather than launching a second competition.

1. Frame caller needs, invariants, accepted domain language, and dependency categories from [DEEPENING.md](DEEPENING.md). Include realistic usage and the complexity an interface must hide. Show this to the user, then immediately proceed to step 2. The user reads and thinks while the sub-agents work in parallel. Complete when each candidate can answer the same design question.
2. Invoke /pstack-arena once. Each candidate must produce a **radically different** interface for the deepened module. Give each a different design constraint: "Minimize the interface: aim for 1–3 entry points max. Maximise leverage per entry point."; "Maximise flexibility: support many use cases and extension."; "Optimise for the most common caller: make the default case trivial."; and, if applicable, "Design around ports & adapters for cross-seam dependencies." Scale candidate count and concurrency to the decision. Supply the resolved vocabulary, project artifacts, and exact scope. Each candidate outputs its interface (types, methods, params, plus invariants, ordering, error modes), a usage example showing how callers use it, what the implementation hides behind the seam, its dependency strategy and adapters, and trade-offs: where leverage is high, where it's thin. Complete when useful independent candidates have evidence or the loss of independence is disclosed.
3. Present designs sequentially so the user can absorb each one, then compare them in prose by depth, locality, seam placement, and caller burden. Recommend one or a concrete synthesis. Be opinionated: the user wants a strong read, not a menu. Preserve any requested interface gate, and invoke /domain-modeling for accepted domain changes and qualifying decisions. Complete when the chosen interface and its durable rationale agree.
