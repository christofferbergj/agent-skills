## Local adaptations to preserve

- The [library-wide adaptations](../../agents/maintain-skills/references/ADAPTATION.md#library-wide-adaptations) apply; this list holds only this skill's own divergences.
- The description is a short human-facing summary without Cursor's Grok Bot, because the skill keeps upstream's user invocation and this repository gives user-invoked skills one.
- Works against an existing receiver's documented contract and stops when none exists. Upstream's routine creation (`update_state`), routine-panel URL and sender-key steps, `SendToUser` secret request, and `[routine]` wake format are Cursor mechanics, so the skill does not invent a webhook service, and the sender key comes through the environment's existing secure mechanism. Claude Code's cloud scheduled tasks, formerly routines, take an API trigger whose URL and bearer token the user creates on the web, and a task with one counts as an existing receiver; creating one from this skill is left out (owner decision, 2026-10-25). Codex documents no inbound webhook trigger.
- Replaces upstream's fixed request (Bearer and `X-Automation-Key` headers, 8-second timeout, one try, HTTP 200 means the routine woke) with the receiver's documented headers, timeout, retry rule, and success signal, because those values describe Cursor's endpoint. The failure log is drained only by a receiver that can read it, instead of by the Cursor routine.
- Binds to localhost and exposes the page on the tailnet only when the user asks; upstream always binds `0.0.0.0` and joins the tailnet, because Cursor's agent computer is remote, while Codex and Claude Code usually run where the user can open localhost.
- Follows Tailscale's current documented setup for the operating system instead of upstream's Linux-only `install.sh` and its `sudo tailscale up` line, because install and start commands differ on macOS hosts, and drops upstream's statement that agents on this computer share one node, which describes Cursor's machine.
