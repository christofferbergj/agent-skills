## Hook and dotenv fixture findings

Ran only fake command strings through the original Claude hook. `git push origin main` exits 2. It exits 0 for `git -C /tmp/fixture push origin main`, `git --no-pager push origin main`, `git clean -df`, and `git branch --delete --force example`. It also exits 0 when `jq` is absent, and falsely blocks `echo "git push is denied"`. No Git mutation ran. This matches upstream's documented frozen-skill limitations. A portable setup needs verified Claude and Codex adapters, a clear unavailable-capability result, and an honest description of parsing limits. [Hook source](https://github.com/mattpocock/skills/blob/49dd158d1076134a641b33efb035946536778336/skills/misc/git-guardrails-claude-code/scripts/block-dangerous-git.sh), [known limitations](https://github.com/mattpocock/skills/blob/49dd158d1076134a641b33efb035946536778336/.out-of-scope/frozen-misc-skills.md).

The latest wizard template contains useful fixes absent from the installed copy, but its shell-style apostrophe escaping still truncates a dotenv value. With fake input `it's literal`, it writes `TEST_VALUE='it'\''s literal'`; Node v24.22.0 `process.loadEnvFile` reads `it`. The template's grep-based `_existing` and upsert also do not safely consume multiline records. Keep its hidden input, symlink/mode preservation, EOF handling and secret redaction, while matching the consuming repository's parser. [Pinned wizard template](https://github.com/mattpocock/skills/blob/49dd158d1076134a641b33efb035946536778336/skills/engineering/wizard/template.sh).

A candidate encoding passed 13 fake-value round trips through both Node v24.22.0 and dotenv 16.6.1. Use literal single quotes when possible, otherwise literal backticks. Double quotes work only without embedded double quotes or literal `\n`/`\r` sequences. Safe unquoted text can handle remaining embedded quote combinations if there is no comment marker, newline, surrounding whitespace or leading quote. Reject unsupported mixtures, carriage returns and NUL rather than alter values. The tests covered empty values, whitespace, both quote types, trailing backslashes, dollar syntax, literal newlines, `#`, backticks and a following sentinel variable. This is dotenv syntax, and must never be passed to shell `source`. Multiline persistence still requires a record-aware reader/writer. [Audited dotenv 16.6.1 parser](https://github.com/motdotla/dotenv/blob/v16.6.1/lib/main.js).
