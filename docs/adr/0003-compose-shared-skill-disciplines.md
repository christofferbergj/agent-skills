# Compose shared disciplines across source families

Keep Matt Pocock's familiar entrypoints and Pstack's explicit playbooks in one owned library. Assign reusable behavior one owner: domain-modeling for project artifacts, codebase-design for architectural vocabulary, tdd for behavior tests, code-review for Standards/Spec review, pr for descriptions, and swarm for host execution. Pstack's specialized evidence and adversarial lenses build on these owners. This keeps existing commands useful while avoiding two coordinators, duplicate specs or glossaries, and conflicting defaults.

Preserve existing project artifact roles, including legacy context/domain files, and use the current upstream glossary/ADR defaults only when no project convention already exists. The coordinator reconciles canonical docs; delegates propose changes. A new source family or helper never overrides an accepted project decision or action boundary.

The 2026-10-16 principle integration adds the locally authored `/principles` owner for selection and composition. Matt's interview, spec, ticket, implementation, testing, and review stages and Pstack's router use it without implicit mode activation. It discovers principle owners from their installed descriptions and reads selected rules at their source. Workers receive explicit resolved instructions; accepted decisions remain in the existing project artifacts. Principle definitions and triggers are not copied into the selector.

Resolve migration strategy in the migration principle rather than conflicting workflow defaults. It chooses coordinated caller replacement when possible and expand-contract when compatibility or release obligations require it, with explicit intermediate and final gates. Sequencing and outcome principles use that owner. Test-quality criteria live in the behavior-testing principle; `/tdd` owns the red/green mechanics and its examples respect contract-observable effects. Human confirmation and action grants remain part of the calling workflow.

User exclusions, reusable experimental inclusion, and these compatibility choices remain local adaptations during upstream review.
