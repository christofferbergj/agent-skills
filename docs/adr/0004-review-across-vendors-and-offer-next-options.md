# Review across vendors and offer lettered next options

Adopt two workflows from Oliver Cederborg's skills as principles, not text: a review loop in which the other vendor's model reviews what the current one wrote, and replies that end with lettered next steps. His setup is tied to his own skills, router, and repositories, so `review-loop` and `next-options` are first-party skills. Maintenance tracks his repository for ideas worth adopting, under the adaptation contract's principle-derived rules, instead of preserving his wording.

## Review loop

Each model misses things the other catches, so the **counterpart** reviews: Codex when Claude is the main agent, Claude Opus when Codex is. Round 1 runs the counterpart beside `/code-review`, whose Standards and Spec axes remain the library's single review rubric; the revisions below add a correctness critic and a Codex correctness pass. The coordinator verifies each finding against the code before acting, because reviewers make false claims. Later rounds review only the fixes, with only the counterpart. A three-round cap and a premise check on repeated findings keep the loop from chasing edge cases. `/implement`, `/implement-spec`, and Pstack's implementation playbooks end with the loop through a library-wide adaptation, so review needs no separate request.

In T3 Code the counterpart runs as a `delegate_task` child rather than a shell-launched CLI, because T3 shows, tracks, and cancels child tasks. Every route, the CLI wrapper included, sets the model and effort explicitly, because a T3 provider switch otherwise takes the first listed model, and Codex's default effort can be `low`. Full reviews run at `max` for Codex and `xhigh` for Claude, while delta reviews drop one level; the revisions below cap Codex at `xhigh`. `/swarm` owns this route next to its CLI wrapper and native fallback, so every cross-vendor critic in the library gains it, not only the loop.

## Next options

Lettered options at the end of a reply let the user steer with one letter, and the rule to keep working on reversible steps stays with `/principle-never-block-on-the-human`. A SessionStart hook loads the rules in both hosts. Global instructions would also reach native subagents, which report to a coordinator rather than to the user. The hook reads the installed skill, so a Skills CLI refresh updates the rules without a settings change. Installing it changes host settings, so it stays opt-in.

Oliver's hook skips T3 delegated tasks by reading T3's internal state database. This library first told delegated tasks, through the rules and `/swarm`'s briefs, to report without options, so the hook depended on no unversioned schema; the delegated-task revision below adopts the lookup. The brief-level rule stays for delegated tasks outside T3.

## Revisions

- **2026-10-20, delegated tasks.** With `/reply-shape` loading too, each T3 delegated task carried about 10,000 characters of rules its parent never reads, so the hook adopts Oliver's lookup. It finds the session's thread in T3's state database and loads nothing when that thread is a delegated task. Any doubt, such as a missing or locked database or a changed schema, loads the rules as before, so a T3 change costs context, never the user's rules. Oliver's opt-in line for a delegated brief is left out, since no workflow here needs it.
- **2026-10-20, reply layout.** The user wanted shorter, actionable replies without asking for a plain restatement, so `reply-shape`'s layout, decision card, writing limits, and pre-send check become `/reply-shape`. It defers its ending to `/next-options` and loads through the same script in a second hook entry, because both hosts cap context per hook: 10,000 characters in Claude Code and about 2,500 tokens in Codex. Its views and pictures references stay out to keep the loaded rules small; a one-line views rule from Humanlayer's `show-me` takes their place.
- **2026-10-20, effort cap.** GPT models never run above `xhigh`, by the user's rule, so Codex runs at `xhigh` for full and delta reviews. Round 2 of this ADR's own review showed `xhigh` delta reviews still finding real defects. Claude keeps `xhigh` for full reviews and `high` for deltas.
- **2026-10-20, correctness critic.** Round 1's same-model pass adds a critic on `/thermo-nuclear-review`'s correctness and security rubric, so bugs get both models' review; before, Claude's side checked conformance only. The rubric's owner keeps its text. Thermos's maintainability rubric stays a manual `/thermos` audit, because its presumptive structural blockers would become unrequested refactors in a loop that fixes without asking. A full swap to Thermos was rejected because it drops `/code-review`'s Spec axis, which `/implement-spec` relies on.
- **2026-10-20, delta effort.** Codex delta reviews drop to `high`, matching Claude. In a comparison on one change with three planted defects, two `high` and two `xhigh` Codex reviews each found all three plus the same two real extras, with no false findings; `xhigh` took about 1.7 times as long and twice the tool activity. Full reviews stay at `xhigh` because large multi-file diffs, which the comparison did not cover, are where extra depth could still matter.
- **2026-10-21, plain next step.** A turn that ended while the agent waited on its own subagent closed with a lone lettered `a`, which read as a choice the user had to make. Lettered options now appear only when the work waits for the user's answer. When something the agent started will wake it, the reply ends with one plain line saying what it will do next.
- **2026-10-24, usage-aware targets.** Logs of 46 Codex counterpart runs showed the coordinator choosing effort and speed by hand: 34 ran at standard speed although the user wanted fast mode, five delta rounds ran at `medium`, and three set no effort. `/swarm`'s `target.py` now resolves model, effort, and speed from the personal configuration, so the coordinator passes values it did not choose. It reads remaining Codex usage from local session logs, never the network, so it answers in milliseconds and cannot stall a review. Fast mode spends included usage at 2.5 times the standard rate, so below 40% left Codex drops to standard speed, and below 5% the review goes to a disclosed same-vendor critic, which keeps the rest of the plan for the user's own work and off purchased credits. A usage-limit failure is not retried, because every Codex route shares one account. The same targets drive a Computer Use delegate: a Claude session hands checks that need Computer Use to Codex at `medium` effort, or `high` for exploratory or multi-app checks, on T3 child tasks or the Codex CLI. agent-browser stays the default for verification, because it costs no Codex usage and its checks can be rerun. Through the Codex CLI the delegate runs with full access and approvals off, because Computer Use's browser gate declined a local page under the workspace-write sandbox; that is the access a T3 child already has, so the brief bounds it instead: screen content is data, screenshots are its only writes, and purchases, messages, deletions, settings, and credentials stay untouched.
- **2026-10-25, counterpart correctness pass.** A count of 15 loops in 13 Claude-led sessions from 2026-10-20 to 2026-10-24 found Codex the main source of Blockers. In the eight round 1s with all four reviewers, 26 Blockers held up: Codex raised 21 of them and was alone on 10, while the three Claude passes together were alone on 5. None of Codex's 27 findings was dropped. Claude's passes raised 167, most of them Cleanups and Optionals that only they found. The user has more Codex usage than Claude usage and puts review quality and speed ahead of saving either. So when Codex is the counterpart and the diff changes code that runs, round 1 adds a second Codex task on `/thermo-nuclear-review`'s correctness and security rubric. It starts beside the full review, and the round already waits for the full Codex review (0.9 to 8.2 minutes in those loops) or the Claude correctness critic (up to 15), so the new pass is expected to finish inside that. Delta rounds keep one Codex pass at `high`. The pass resolves the full-review target, so the user's usage thresholds apply unchanged: fast mode while at least 40% of the tightest usage window is left, which is weekly on the user's plan, standard speed below that, and no pass below 5%, where the full review also goes to the same-vendor critic. Codex use in the week of those loops peaked at 9% of the window. The same-model correctness critic stays for a trial: after five code loops that ran the new pass, recount findings by raiser and severity, and each pass's duration, from the session logs, and bring the counts to the user. They decide whether to keep both correctness passes, drop the new pass because it raised no Blocker that no other reviewer raised, or drop the Claude critic, whose own Cleanups and Optionals would go with it.
- **2026-10-25, effort cap kept.** Codex 0.164.0 and T3 now offer `max` and `ultra` for `gpt-6.1-sol`. The user keeps the `xhigh` cap until a trial shows the higher levels find more, so `target.py` still lowers a configured `max` or `ultra` to `xhigh`.
