# Coordinate T3 projects from a pinned thread

The user asked on 2026-10-31 to adopt Oliver Cederborg's `coordinator`, which runs a multi-PR project from one pinned T3 Code thread. The library already had two coordinators. /pstack-mode's Orchestrate playbook runs a standing program on any host, and Matt Pocock's /chief-of-staff pursues a long-running goal in one session with a wiki for memory. Neither uses what T3 Code adds: child tasks in their own worktrees, PR watches that wake the thread, timers bound to it, and pending questions that workers ask mid-run. Without those, the user has to come back to check on each worker, and calls arrive scattered across threads.

So `coordinator` is a first-party skill built on Oliver's ideas, like `review-loop`, `next-options`, and `reply-shape` ([ADR 0004](0004-review-across-vendors-and-offer-next-options.md)). It keeps his model: one pinned `◆` thread is the only place the user talks to, a project file is the memory, workers own their branches, two slots bound the builds, and the user gets one decision card at a time. It reaches this library's owners for everything else. Workers run /pstack-mode's playbooks and end at a draft PR whose final review is /review-loop. /swarm's T3 route and model roles set each child's brief and target. Its cards and its list of real calls are self-contained, because /reply-shape and /next-options are user-invoked and load only through their opt-in hook; when active, /reply-shape lays the cards out. Watch events go to Babysit passes, and merges go through Shipping, on the user's go. Oliver's router modes, per-repository merge trust, merge-gate hook, and tower are left out, since this library ships none of them.

Orchestrate stays, because it is sourced Pstack text that runs anywhere. The coordinator restates several of its supervision rules in T3 terms, such as piloting one unit, checking a PR's live state, and retrying by cause, rather than citing a playbook whose host-neutral rules forbid what a T3 coordinator needs: a project script, an hourly heartbeat, and handing watch events to owners. The skill is model-invoked, as upstream's is, so a heartbeat, a worker's completion, or a compaction in a coordinator thread reloads it.

T3 Code replays interval timers missed while the machine slept, so every coordinator timer opens with the user's run gate for interval tasks. Workers on another machine are left out until the user links one.
